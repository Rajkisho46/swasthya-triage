## Architecture Dissection

### A. What is Actually Real (Live Backend / Database)
1. **FastAPI HTTP Endpoints**: Real routes mounted at `/api/auth`, `/api/intake`, `/api/triage`, `/api/review`, `/api/patient`, `/api/cases`, `/api/referral`, `/api/audit`.
2. **SQLite Database Persistence**: Real tables (`cases`, `consents`, `clinical_reviews`, `audit_events`, `bedside_assessments`, `patient_users`) persisted in `server/swasthya_triage.db`.
3. **Deterministic Safety Rules Engine**: Real rule matcher (`DeterministicSafetyRulesEngine` in `server/app/services/rules_engine.py`) evaluating combined narrative for 6 clinical urgency rules.
4. **JWT Authentication & RBAC**: Real bcrypt password checking and HS256 JWT generation with role claim verification (`AuthService`, `deps.py`, `rbac.py`).
5. **Bedside Assessment Ingestion**: Real ORM storage of multi-parameter vitals (BP, SpO2, HR, Temp, Resp Rate) and clinical observations.
6. **Clinical Referral PDF Engine**: Real ReportLab PDF synthesis delivering downloadable clinical documents.

### B. What is Mock / Demo / In-Memory
1. **Frontend Initial State**: `src/App.tsx` initializes state with `SYNTHETIC_SAMPLE_CASES` (`CASE-1001` through `CASE-1005`) from `src/data/sampleCases.ts`.
2. **Offline Audio & OCR Samples**: `src/services/stt/MockSpeechService.ts` and `src/services/ocr/MockOCRService.ts` provide pre-recorded demo assets for offline demonstration.
3. **Demo User Store**: `server/app/utils/security.py` maintains fixed credentials for the 5 institutional demo personas.

### C. What is Partially Connected / Dual-Path
1. **Patient Intake Form Submission**:
   - `PatientIntakeForm.tsx` supports both a client-side deterministic processor and a server-side proxy call (`/api/triage`).
   - Case records generated in the UI are held in React state for immediate workflow transitions; invoking `POST /api/intake` commits them permanently to SQLite.
2. **AI Provider Structuring**:
   - Backend `LLMStructuringService` has a live HTTP client for Google Gemini. When the Gemini model name or key requires adjustment, the server automatically and cleanly activates its deterministic rule-based fallback without breaking the triage workflow.
